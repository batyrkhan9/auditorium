# Contract 0.2.0: answers to the 19 gaps the connectors and the screen found

Draft for both of us to agree. Source: board task #7. Every change is additive:
new fields are optional and existing calls keep working, so nothing already
written against 0.1.0 breaks.

## What was decided for each item

| # | Gap | Answer |
|---|---|---|
| 1 | Ramp's role is a permission level, not a job role | **Changed.** `Person.role` stays the job role and comes from company records. New `Person.platform_role` holds Ramp's. |
| 2 | Ramp download links expire; files are cached outside a dataset folder | **Clarified.** The connector downloads, hashes and serves the file through `Sources.document_file()`. `sha256` stays required: it ties evidence to the exact file read. |
| 3 | Ramp has no `origin` | **Changed.** New `default_origin(type)` so every area infers it the same way. |
| 4 | "Pending" and "never routed" look the same | **Changed.** `Approval.decision` gains `pending` (no `decided_at`). No approval steps at all means never routed. |
| 5 | What "paid" means for a card | **Clarified.** Bill: the day payment left. Card: settlement date. |
| 6 | Bills have no department; several accounts, one `category` | **Deferred.** No check reads either. `category` is the largest line's; the full split stays in `raw`. |
| 7 | Ramp has no policy in this shape | **Clarified.** `SpendPolicy` is company records, also in live mode. |
| 8 | No account type on ledger lines | **Changed.** New `LedgerLine.account_type`. |
| 9 | QuickBooks puts department on the whole entry; class has nowhere to go | **Partly.** New `LedgerEntry.department`. Class stays in `raw`; no check reads it. |
| 10 | Journal entries name a vendor per line | **Changed.** New `LedgerLine.vendor_name`. |
| 11 | Payment type and bill due date only in `raw` | **Deferred.** No check reads them. |
| 12 | Live ledger ids differ from dataset ids | **Rule.** A run is verified against the `Sources` it ran on. Open question below. |
| 13 | The loader needs ledger entries with lines | **Rule, and a request to data.** The scored dataset's entries carry balanced lines with account types. The contract's example now does. |
| 14 | Sign-off only per result | **Changed.** New `LogWriter.sign_off_run`. |
| 15 | Cannot mark data as synthetic | **Changed.** `DatasetManifest.synthetic`, `RunManifest.synthetic_data`. |
| 16 | A run does not say where its dataset lives | **Changed.** New `RunManifest.dataset_path`. |
| 17, 18 | Two writers can fork the log's chain | **Fixed.** Every append takes an exclusive file lock and reads the last line under it. `LogWriter` no longer keeps the chain's state in memory. Tested with 8 threads. |
| 19 | A sign-off is not tied to what the result said | **Changed.** `sign_off(..., result=result)` stores the result's hash. `validate_run` reports a result changed after sign-off. |

## Why additive

Three areas already have code on branches against 0.1.0. A breaking change
would cost each of them a rework during a hackathon. Optional fields cost
nothing today and each area adopts them when it gets there.

## Why `sha256` stays required (item 2)

Dropping it would make live documents easier to list. But the hash is what lets
a reviewer confirm that the page the agent quoted is the file they are looking
at. Downloading a few hundred receipts once is a small price for that.

## Why items 6, 9 (class) and 11 are deferred

Each would add fields no check reads. They are in `raw` if a check ever needs
them, and adding a field later is cheap.

## Open question for both of us (item 12)

Evidence from a live run can only be re-verified while the live data is
unchanged. Should a run save a copy of what its `Sources` returned into the run
folder, so it can be verified later from the folder alone? It fits "the auditor
can verify it without trusting the agent", and it is not built.

## What each area does once this merges

- **agent**: read `LedgerLine.vendor_name` and `account_type` in the accrual
  search; say "pending" instead of "none" when an approval is waiting; fill
  `dataset_path` and `synthetic_data`.
- **data**: ledger lines with account types on every entry; job roles and
  managers in `people.jsonl`; `synthetic: true`.
- **connectors**: fill `platform_role`, pending approval steps, line vendors,
  account types, entry department; use `default_origin`.
- **ui**: pass `result=` to `sign_off`; use `sign_off_run`; show a banner when
  `synthetic_data` is true. The guard that refuses sign-off while a run is
  unfinished is no longer needed for the log's safety.
- **evals**: verify each run against the `Sources` it ran on.

## What was checked

The test suites of `ui/run-viewer`, `connectors/quickbooks` and
`connectors/ramp-demo` were run against this contract and all pass unchanged
(15, 28, and 13 with 1 skipped). The first draft added a `scope` key to
per-result sign-offs and broke one ui test, so that key was removed: only a
run sign-off carries `scope: run`.

Not checked: the file lock on Windows, and anything against live payloads.

## Round 2, 2026-11-10: after Noriaki's review

He reproduced five bugs in the first draft and disagreed on three answers. All
five are fixed, each with a test, and he was right on all three.

**Bugs fixed**

| What he found | Fix |
|---|---|
| A cut-off last line broke every later append | `LogWriter` refuses with a `LogDamaged` error that names the repair. `repair_log` removes the damaged end and keeps it in `<log>.damaged`. |
| A last line with no line ending merged with the next event | Appends check the file ends cleanly first. `repair_log` adds the ending if the event is whole. |
| The result hash covered default fields, so any new optional field would flag every signed result | `result_hash` leaves out fields at their defaults. Tested with a subclass that adds fields. |
| A re-signed result was reported forever | Only the latest sign-off of each result is checked. |
| A sign-off pinned what was on disk, not what the reviewer saw | `sign_off` takes `result_sha256`, the hash the screen took when it rendered the page, and refuses if the result changed meanwhile. |

**Answers changed**

- **Unknown attachments are internal.** `default_origin("other")` now returns
  `internal`. Calling an unidentified file external claims more than we know.
- **`LedgerEntry.payment_type` added.** I deferred it because no check reads
  it. The QuickBooks loader does, and reading it from `raw` made `raw` a private
  format between two areas, which our own rules forbid.
- **The screen keeps its rule** of no sign-off before the run finishes. The
  contract now enforces the same for run sign-offs.

**Added from his notes**

- People join on email; Ramp's ids and manager win.
- A pending approval may have no approver yet, and never has a decision time.
  An empty approvals list means never routed; `None` means the source could not
  say.
- A run sign-off pins `results.jsonl` and `run.json` and must follow
  `run_finished`.
- Synthetic is set per source by whoever implements it; the run reads it.
- `validate_run` now checks each document file against its recorded `sha256`.
  That was the reason given for keeping the hash required, and it was not
  actually enforced.
- Rules written into the contract: category tie-break, QuickBooks AccountType
  names, line-level department only, entry vendor only when all lines agree,
  exactly one balancing line on bills and expenses, resolved dataset path.

**The snapshot (item 12), built as he proposed**

`log_source_fingerprints` writes a sha256 per kind of record into the log at
fetch time. `snapshot_sources` saves what was fetched into the run folder.
`validate_run` with no sources ties the snapshot to the logged fingerprints and
verifies against it. The output says "verified against snapshot" or "against
the sources given", never just "verified", because a snapshot shows the data is
unchanged since the fetch, not that the fetch was honest.

**What the agent must change once this merges**

Call the two snapshot functions; treat `approvals is None` as `needs_review`,
not as "no approval"; read line vendors and account types in the accrual
search; fill `dataset_path`.

**Checked.** 38 tests here. Against the current heads of `ui/run-viewer`
(3702f25), `connectors/ramp-demo` (ee15b55), `connectors/quickbooks` (7a2b18c)
and `agent/claude-reader` (ad7bb0c), each area's own tests pass unchanged: 22,
69 with 1 skipped, 28, and 23. Not checked: the file lock on Windows, live
payloads, and `repair_log` on anything but the two cases he reported.

## Round 3, 2026-11-10: three more from Noriaki's review

He checked round 2, found all five fixes held, and reproduced three new
problems. All three are fixed, each with a test that fails on the old code.

| What he found | Fix |
|---|---|
| A. `approvals=None` came back from disk as an empty list. "The source could not say" turned into "never sent for approval", which the approval check fails: a false alarm. The same loss made an untouched snapshot look tampered. | `SpendTransaction` always writes `approvals: null`, even when the caller leaves None values out. Files, fingerprints and snapshots all keep it. |
| B. `validate_run` crashed on a `source_call` event with a `sha256` but no `call`, such as a logged document download. | Only events with both are read as fingerprints. |
| C. `repair_log` removed a last event that had been edited, and the chain then read clean. | It removes only a line that is cut off or does not read as an event. A complete event that does not match its hash is refused with `LogDamaged`, and the file is left as it was. The `repair-log` command prints why and exits 1. |

**Why A is fixed by writing null, not by changing the default.** He offered
both. Defaulting `approvals` to None would change what existing code means: a
transaction built without approvals would become "unknown", and code that loops
over the list would crash on None until every area handled it. Writing null
changes nothing for records that never use None. A record with no `approvals`
key still reads as an empty list.

**Why the fix sits on the model, not in `write_jsonl`.** Any code that dumps a
transaction without None values would repeat the bug. On the model, there is
one place and no way to forget it. Leaving the field out on purpose
(`exclude`, `include`) still works.

**Not in this round**, by choice, so the three blockers can merge:

- D. Flagging a sign-off that has no `result_sha256`. The screen switches to the
  pinned call once this merges.
- A way to mark a document Ramp lists but cannot serve.
- A sanctioned place for values a connector took from the dataset instead of
  Ramp. Today they sit under `raw["auditorium_replaced_from_dataset"]`.
- Answers on Ramp card department, the sandbox's two legal entities, and UTC
  dates. The data area posted the dataset's facts on each (board #7).

38; that was the whole repo, and Noriaki's count of 24 for the contract was
right). Each of the five new tests fails on the round 2 code. Each area's own
tests against this contract, unchanged: `connectors/ramp-loader` 4773a7d (188,
