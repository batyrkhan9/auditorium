# Contract 0.2.0: answers to the 19 gaps the connectors and the screen found

Draft for both of us to agree. Source: board task #7. Every change is additive:
new fields are optional and existing calls keep working, so nothing already
written against 0.1.0 breaks.

## What was decided for each item

| # | Gap | Answer |
|---|---|---|
| 1 | Ramp's role is a permission level, not a job role | **Changed.** `Person.role` stays the job role and comes from company records. New `Person.platform_role` holds Ramp's. |
| 2 | Ramp download links expire; files are cached outside a dataset folder | **Clarified.** The connector downloads, hashes and serves the file through `Sources.document_file()`. `sha256` stays required: it ties evidence to the exact file read. |
| 3 | Ramp has no `origin` | **Changed.** New `default_origin(type)` so every area infers it the same way. |
| 4 | "Pending" and "never routed" look the same | **Changed.** `Approval.decision` gains `pending` (no `decided_at`). No approval steps at all means never routed. |
| 5 | What "paid" means for a card | **Clarified.** Bill: the day payment left. Card: settlement date. |
| 6 | Bills have no department; several accounts, one `category` | **Deferred.** No check reads either. `category` is the largest line's; the full split stays in `raw`. |
| 7 | Ramp has no policy in this shape | **Clarified.** `SpendPolicy` is company records, also in live mode. |
| 8 | No account type on ledger lines | **Changed.** New `LedgerLine.account_type`. |
| 9 | QuickBooks puts department on the whole entry; class has nowhere to go | **Partly.** New `LedgerEntry.department`. Class stays in `raw`; no check reads it. |
| 10 | Journal entries name a vendor per line | **Changed.** New `LedgerLine.vendor_name`. |
| 11 | Payment type and bill due date only in `raw` | **Deferred.** No check reads them. |
| 12 | Live ledger ids differ from dataset ids | **Rule.** A run is verified against the `Sources` it ran on. Open question below. |
| 13 | The loader needs ledger entries with lines | **Rule, and a request to data.** The scored dataset's entries carry balanced lines with account types. The contract's example now does. |
| 14 | Sign-off only per result | **Changed.** New `LogWriter.sign_off_run`. |
| 15 | Cannot mark data as synthetic | **Changed.** `DatasetManifest.synthetic`, `RunManifest.synthetic_data`. |
| 16 | A run does not say where its dataset lives | **Changed.** New `RunManifest.dataset_path`. |
| 17, 18 | Two writers can fork the log's chain | **Fixed.** Every append takes an exclusive file lock and reads the last line under it. `LogWriter` no longer keeps the chain's state in memory. Tested with 8 threads. |
| 19 | A sign-off is not tied to what the result said | **Changed.** `sign_off(..., result=result)` stores the result's hash. `validate_run` reports a result changed after sign-off. |

## Why additive

Three areas already have code on branches against 0.1.0. A breaking change
would cost each of them a rework during a hackathon. Optional fields cost
nothing today and each area adopts them when it gets there.

## Why `sha256` stays required (item 2)

Dropping it would make live documents easier to list. But the hash is what lets
a reviewer confirm that the page the agent quoted is the file they are looking
at. Downloading a few hundred receipts once is a small price for that.

## Why items 6, 9 (class) and 11 are deferred

Each would add fields no check reads. They are in `raw` if a check ever needs
them, and adding a field later is cheap.

## Open question for both of us (item 12)

Evidence from a live run can only be re-verified while the live data is
unchanged. Should a run save a copy of what its `Sources` returned into the run
folder, so it can be verified later from the folder alone? It fits "the auditor
can verify it without trusting the agent", and it is not built.

## What each area does once this merges

- **agent**: read `LedgerLine.vendor_name` and `account_type` in the accrual
  search; say "pending" instead of "none" when an approval is waiting; fill
  `dataset_path` and `synthetic_data`.
- **data**: ledger lines with account types on every entry; job roles and
  managers in `people.jsonl`; `synthetic: true`.
- **connectors**: fill `platform_role`, pending approval steps, line vendors,
  account types, entry department; use `default_origin`.
- **ui**: pass `result=` to `sign_off`; use `sign_off_run`; show a banner when
  `synthetic_data` is true. The guard that refuses sign-off while a run is
  unfinished is no longer needed for the log's safety.
- **evals**: verify each run against the `Sources` it ran on.

## What was checked

The test suites of `ui/run-viewer`, `connectors/quickbooks` and
`connectors/ramp-demo` were run against this contract and all pass unchanged
(15, 28, and 13 with 1 skipped). The first draft added a `scope` key to
per-result sign-offs and broke one ui test, so that key was removed: only a
run sign-off carries `scope: run`.

Not checked: the file lock on Windows, and anything against live payloads.
